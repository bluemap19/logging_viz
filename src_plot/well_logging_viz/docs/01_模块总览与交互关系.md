# 模块总览与交互关系

## 1. 架构概览

`well_logging_viz` 目录包含 5 个 Python 文件，共同构成一个**模块化测井数据可视化系统**：

```
well_logging_viz/
├── __init__.py              # 空包标记文件
├── cache_logging.py         # 缓存层：LRU + zlib 压缩
├── data_manager.py          # 数据管理层：验证、配置检查、可见窗口提取
├── data_visulization.py     # 可视化层：Matplotlib 多面板绑定
└── docs/                    # 设计文档目录
    ├── 01_模块总览与交互关系.md
    ├── 02_cache_logging_设计文档.md
    ├── 03_data_manager_设计文档.md
    ├── 04_data_visulization_设计文档.md
    └── 05_岩心数据叠加绘制_设计文档.md
```

## 2. 各模块职责

### `cache_logging.py` — 缓存系统

**职责**：提供三层 LRU 缓存，管理常规测井数据（DataFrame）、FMI 图像（List[np.ndarray]）、NMR 谱数据（List[np.ndarray]），支持 zlib 压缩和命中率统计。

**核心类**：`EnhancedWellLogCache`

**对外接口**：

| 方法 | 说明 |
|------|------|
| `get_data(depth_range)` | 获取常规测井数据缓存 |
| `set_data(depth_range, df)` | 设置常规测井数据缓存 |
| `get_fmi_data(depth_range)` | 获取 FMI 图像缓存 |
| `set_fmi_data(depth_range, images)` | 设置 FMI 图像缓存 |
| `get_nmr_data(depth_range)` | 获取 NMR 谱缓存 |
| `set_nmr_data(depth_range, nmr_arrays)` | 设置 NMR 谱缓存 |
| `get_memory_usage()` | 获取内存使用统计 |
| `get_cache_stats()` | 获取缓存命中率统计 |
| `record_core_access()` | 记录岩心数据访问（复用常规测井缓存） |

**内部机制**：

- 使用 `OrderedDict` 实现 LRU 淘汰
- FMI/NMR 缓存启用 zlib 压缩，压缩比通常 2-5x
- 支持最大缓存条数、最大内存上限、最大条目大小限制
- `max_entry_size`：单条数据超过此阈值（默认 50MB）则跳过缓存

---

### `data_manager.py` — 数据管理器

**职责**：管理原始数据的输入、验证、配置智能补全，以及给定深度窗口的可见数据提取。

**核心类**：`LoggingDataManager`

**对外接口**：

| 方法 | 说明 |
|------|------|
| `__init__(logging_data, fmi_data, nmr_data, config_core)` | 初始化（支持岩心配置） |
| `plot_config_check(...)` | 配置智能检查与自动补全，返回完整配置字典 |
| `get_visible_logging_data(top, bottom)` | 获取常规测井可见窗口（带缓存） |
| `get_visible_fmi_data(top, bottom)` | 获取 FMI 图像可见窗口（带缓存） |
| `get_visible_nmr_data(top, bottom)` | 获取 NMR 谱可见窗口（带缓存） |
| `_validate_and_adapt_core_config(config)` | **新增**：验证岩心配置 |
| `get_performance_stats()` | 缓存命中率统计 |
| `cal_plot_num()` | 计算子图总数（FMI + 曲线 + 分类 + NMR） |
| `close()` | 清空缓存，释放资源 |

**配置检查流程**：

```
用户配置 + 默认配置模板
    ↓ _deep_merge_configs（递归合并）
合并后配置
    ↓ _validate_and_adapt_xxx_config（各类型独立验证）
最终配置
    ↓ _log_config_check_results（日志记录）
返回 validated_configs
```

---

### `data_visulization.py` — 可视化器

**职责**：基于 Matplotlib Figure 创建多面板绑定图，按深度窗口渲染测井曲线、FMI 图像、NMR 谱、岩性分类和岩心杆状图。

**核心类**：`WellLogVisualizer`

**对外接口**：

| 方法 | 说明 |
|------|------|
| `__init__(data_manager, ..., config_core)` | 初始化（含岩心配置参数） |
| `visualize(top_depth, bottom_depth)` | 核心渲染方法：创建/刷新整张图 |
| `_plot_all_core_lines()` | **新增**：初始绘制岩心杆状图 |
| `_update_core_lines()` | **新增**：刷新岩心杆状图（深度窗口变化） |
| `_get_curve_axes_indices()` | **新增**：获取曲线道→轴索引映射 |
| `_update_display(top, bottom)` | 刷新所有面板（深度拖动时调用） |

**面板布局顺序**：

```
axs[0]              axs[n_fmi_panels-1]      # FMI 电成像面板
axs[n_fmi_panels]  axs[...curve...]          # 常规曲线面板
axs[...curve...]   axs[...type...]           # 岩性分类面板
axs[...type...]    axs[last]                 # NMR 谱面板
```

**注意**：岩心杆状图**不占用独立面板**，而是叠加绘制在已有曲线道的上方区域（X 轴右侧 60%~95% 区间）。

## 3. 模块间交互关系

```
用户 / 上层调用
    │
    ├──────────────────────────────────────────┐
    │                                          │
    ▼                                          ▼
┌─────────────────┐                   ┌─────────────────┐
│ LoggingDataManager │                │ WellLogVisualizer │
│  data_manager.py  │                 │ data_visulization.py │
└────────┬────────┘                   └────────┬────────┘
         │                                      │
         │ 持有                                 │ 持有
         ├─ cache_system (EnhancedWellLogCache)│
         │                                      │
         │ 持有                                 │ 调用（get_visible_xxx）
         ├─ logging_data (DataFrame)           ├─ get_visible_logging_data()
         ├─ fmi_data (dict)                    ├─ get_visible_fmi_data()
         ├─ nmr_data (dict)                    └─ get_visible_nmr_data()
         └─ config_core (dict)─────────────────────► 读取并使用
                │
                │ 岩心配置
                │ (core_curves, plot_index_list,
                │  thicknesses, colors, range)
                ▼
         ┌─────────────────┐
         │ EnhancedWellLogCache │
         │  cache_logging.py   │
         └─────────────────┘
```

## 4. 岩心数据在架构中的位置

岩心数据（`core_data`）是**稀疏 DataFrame**（大部分深度点为 NaN），其设计特点：

1. **存储**：存储在 `logging_data` DataFrame 的特定列中，不单独存储
2. **缓存**：复用常规测井数据的 LRU 缓存（通过 `record_core_access()` 统计访问）
3. **配置**：通过 `config_core` 字典传入，验证逻辑在 `data_manager.py`
4. **可视化**：以**水平短线（杆状图）叠加绘制**在已有曲线道的 X 轴右侧，不占用独立面板
5. **更新**：深度窗口变化时调用 `_update_core_lines()` 刷新

---

## 5. 关键设计决策

| 决策 | 理由 |
|------|------|
| 岩心数据复用 logging_data 缓存 | 避免重复存储，节省内存；岩心列与常规列共存在同一 DataFrame |
| 岩心叠加绘制而非独立面板 | 测井图道资源宝贵；岩心数据稀疏，独立面板利用率低 |
| 杆粗细用曲线值归一化决定 | 直观反映岩心数据幅值大小 |
| 归一化到 X 轴 60%~95% 区间 | 避免遮挡常规测井曲线，留出足够视觉空间 |
